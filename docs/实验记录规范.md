# 实验记录与结果归档

版本 v3，2026 年 11 月 17 日。用于 World4Scorer 与 NAVSIM 主实验 E0–E4，以及选做的闭环验证 E5，实验定义见[研究方向与实验设计](论文方向与实验设计_修订版.md)。

## 每次运行的记录

每次运行使用独立运行编号。一个编号对应确定的基准、阶段、方法、权重、数据划分、评测协议和种子。席位或环境改变时另留实际环境文件。按照[实验记录模板](../templates/实验记录模板.csv)记录摘要，用相对路径指向不可缺少的原始数据。

| 文件或字段 | 内容 |
| --- | --- |
| `manifest.json`、`env.txt` | 运行人、时间、阶段、意图、操作系统和机器、CPU/GPU、驱动、Python 与关键依赖、World4Scorer／NAVSIM 或 Bench2Drive 提交、CARLA 版本、权重 SHA-256 |
| `command.sh` 或命令记录、冻结配置 | 完整可运行命令、提交与配置指纹、推理批量和分片、随机种子、重排设置、控制器、子集文件与规则版本。记录实际路径别名，移除密钥 |
| `split.csv` 或 `routes.csv` | 数据版本、样本或路线 ID、日志或场景族、集合用途、入选理由、期望分母。开发与正式清单分开存放 |
| `run.log`、原始输出 | 环境和执行日志、逐 token CSV、逐路线 JSON、候选池与标签文件索引、重复失效和环境异常 |
| `metrics.csv`、`figures/` | 由原始输出计算的汇总、分项、分子分母、图表、图注及绘图命令 |
| `review.md` | 实测结论、异常解释、当前证据支持的范围和下一步 |

## 三层结果如何对应

- **场景层**按 `token`、`log_name`、`pool_hash` 记录候选集和方法。保留官方分项、`selected_id`、分岔和碰撞时间、是否存在安全有效候选、配对的运行 ID。场景时间轴使用统一基准时刻。
- **候选层**按 `pool_hash + token + candidate_id` 关联轨迹、仿真标签、模型分和选择。对于分时方法，另带时刻（秒）、对应标签定义、可用帧与掩码。标明单位、轨迹参考系及预测与回放来源。标签缺失填空并说明原因。
- **路线层**按 `route_id + 场景配置 + 评测种子` 配对。记录完成状态、驾驶分、完成进度、碰撞类型、终止原因、实际耗时和两版运行证据。保留上游原始记录和汇总脚本版本。

实验记录 CSV 是运行索引，正式论文使用可从上述原始数据重新生成的指标与图表。开发诊断先检查事件定义、数值单位、候选 ID 对齐及标签缺失，样本或路线重复时保留重试记录并明确最终纳入者。

## 分母与状态

| 状态 | 处理 |
| --- | --- |
| 完成或真实模型失败 | 按评测器协议计入，并保留碰撞、超时、未完成路线等指标 |
| 数据、模拟器、依赖或基础设备故障 | 单独记录实际原因，按冻结规则重试。最终保留异常状态和配对缺口，报告有效数与期望数 |
| 未执行、标签缺失 | 使用空值或 `NA` 并说明，保留缺失所占比例 |
| 小样本与调试 | 标明数据来源、选取规则和分母，作为开发材料 |
| 作者数据与拟定目标 | 在图表独立标为作者值或目标值，论文项目结果填入实际证据 |

## 正式报告和图表

1. NAVSIM 汇总先写协议、权重、重排口径和完整性，再写 EPDMS 及分项。难例错选率写清固定池、可避免样本数、碰撞判定和前进距离。
2. 保留同一场景的配对改善与回退，并按原始日志给出配对统计区间。路线结果按匹配路线统计。耗时对比注明计时范围、设备、批量和预热配置，保留 P50 与 P95。
3. 主图从全体配对数据绘制。同场景轨迹图注明实际分支时刻、所选候选、评测标签与模型预测。视频可配一条改善路线、一条无差异或回退路线，片段可追溯到成绩表。
4. 记录训练与验证日志的划分和种子，正式评测后若修复正确性错误，在日志记录变更与影响范围并重跑受影响的对照。在冻结表保存脚本、学习增量、权重和最终图表版本。
