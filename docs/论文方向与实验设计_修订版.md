# 论文方向与实验设计

**暂定题目**　《基于世界模型的端到端驾驶轨迹选择方法研究》

**版本**　v3.1，2026-11-18。主实验采用 World4Scorer 与 NAVSIM v2.2。Bench2Drive/CARLA 在主实验完成且机时与适配条件允许时选做。日期见[时间安排](时间安排_v3_世界模型路线.md)，结果归档见[实验入口](../experiments/2026-11-17_world4scorer/README.md)。各项成绩待实测。

## 1. 问题、范围与证据链

World4Scorer 从传感器观测生成候选轨迹，再用共享未来预测模块为每条候选产生状态并评分。本文考察**给定同一批候选，且其中存在安全、有进展的方案时，改进世界模型能否减少危险错选并保持通行进度**。路口通行和车辆切入是首批诊断场景。候选晚分岔是用来隔离分岔前后风险的诊断条件，是否进入主假设由 E2 决定。[World4Scorer 论文](https://arxiv.org/abs/2609.36438) · [官方代码](https://github.com/World4Scorer/World4Scorer)

| 假设 | 要取得的证据 | 判断 |
|---|---|---|
| H1 存在可归因于选择的改进空间 | 同一候选池全部完成评测。找到基线选中有责碰撞轨迹、池中另有安全且进度达线的样本，并统计发生频率和独立日志数。 | 有明确的选错样本，才能讨论怎样改善排序。候选缺失另作覆盖诊断。 |
| H2 风险发生时机与误选有关 | 在同前缀候选对上检查首个风险时刻、分岔时刻、原模型排序。统计错误能否在多个日志和互动场景复现。 | 证据充分时进入分时世界模型分支。 |
| H3 改进能迁移至正式评测 | 在冻结的 NAVSIM 困难集合上比较危险错选率与通行进度，另报告全量 EPDMS 和分项。 | 根据难例的配对结果和全量成绩界定收益及适用范围。 |

论文中的“世界模型”指以当前观测和候选自车动作预测未来状态、并用未来状态给候选评分的模型。主实验固定感知输入、轨迹生成器和候选预算。原模型的世界状态由已执行轨迹未来观测和仿真候选结果共同监督。真实日志对已执行计划有观测，对其它计划只能使用仿真结果。主实验结论限于 NAVSIM v2.2 单阶段非响应回放评测和所覆盖的场景。 [原论文 §3 与附录 B](https://arxiv.org/html/2609.36438v1) · [NAVSIM v2.2 指标说明](https://github.com/autonomousvision/navsim/blob/v2.2/docs/metrics.md)

本机 Windows 作论文与图表整理，Ubuntu 用于代码和小规模验证，服务器用于正式训练或批量推理。先完成 CUDA 和小样本推理验证，记录 Python、PyTorch、CUDA runtime、驱动、GPU、数据版本、代码提交和权重 SHA256。E1 的统计分数和图表由实际运行产物生成。若启动可选闭环，再准备实验室公共机、CARLA 版本和对应的独立环境。

训练标签遵循发布方法的来源边界：

- 已执行轨迹在日志中对应真实未来画面。基线发布特征为前视相机未来 2 秒 DINOv2 表征。若采用分时路线，在训练数据内为 1、2、3 秒分别抽取同一种特征，记录标注时间、采样偏差及可用掩码。
- 生成候选轨迹在冻结环境中仿真执行，可用判定得到有责碰撞、越界和进度等结果。分时分支需**额外实现**从仿真判定或记录事件时刻生成累计风险标签的构建器，例如截至 1、2、3 秒是否已发生有责碰撞。输出 `candidate_id`、事件首时刻、对象类别和各时刻有效掩码，检验时间同步、参考系和漏帧。发布的未来特征和评分 CSV 保持其原有含义，另建时序标签缓存。
- 首次导出后人工复核安全行驶、实际碰撞、无效时序三种样例，核对事件时刻与评测轨迹。对无法取得可靠时序判定的样本保留缺失掩码。几何重叠代理若启用，需记录其独立定义，并在实验指标中与官方有责碰撞判定分列。
- 部署的世界模型只读取当前可用传感器、当前路线信息和候选轨迹。日志未来和仿真标签用于训练、诊断及评测。冻结时保存人员、时间、命令、清单哈希、阈值、主指标、统计代码版本和重跑规则。

## 3. 方法、对照和备用路线

| 组别 | 训练与推理 | 对照用途 |
|---|---|---|
| B0 作者发布模型 | 直接加载对应平台的发布权重。 | 复现外部基线，定位原始失败。 |
| B1 同训练预算原结构 | 从同一发布版本初始化，使用原世界模型和评分结构进行同训练计划的续训。 | 控制继续训练、样本选择、冻结范围和训练预算的影响。 |
| B2 分时全轨迹 | 使用当前观测和候选完整轨迹，分别预测 1、2、3 秒状态并给轨迹评分。 | B2 与 B1 对照分时表示和时序监督带来的整体变化。 |
| B3 分时轨迹前缀 | 与 B2 使用相同网络容量、输入模态、标签、训练步数和损失，对时刻 $t$ 的预测只提供截至 $t$ 的候选自车轨迹。 | B3 与 B2 直接检验读取动作范围的作用。 |
| B3-R 匹配进度的安全排序 | 备用路线，在 B1 原世界模型状态的评分上增加匹配进度的安全/危险成对监督。 | 若 E2 无法支持分时假设，在 B1 与 B3-R 之间验证有明确证据的选择错误。 |

B2 和 B3 以相同当前观测和冻结候选为输入，使用共同的时间嵌入、状态维度、评分层和损失有效值掩码。两组都保留相同全时域评分分支，以覆盖第 3–4 秒的风险，短时未来状态在评分层与该分支融合。B2 在各时刻读取完整轨迹，B3 在各时刻先截断动作输入再编码，或在完整轨迹序列编码前施加等价的因果掩码。检查完整轨迹嵌入、跨候选注意力和全时域评分分支是否将候选后缀值带入短时预测分支。开发阶段使用同前缀但替换后缀的候选对，检查 B3 短时预测一致性，再用独立风险标签和选轨指标检验实际价值。已经由结构保证的一致性用于排除实现错误，性能比较依赖对应的风险及选轨表现。SafeDrive 已有逐时刻风险预测设计，本文对照具体检验输入动作范围的差异。[SafeDrive](https://arxiv.org/abs/2602.18887)

当世界模型输出每一时刻的未来状态时，从状态预测累计风险并保留原有候选质量监督。损失由原候选评分监督、可用时间掩码下的未来视觉特征监督和风险监督组成。B2 与 B3 统一候选排序分数的计算方法、风险权重、时间权重、排序平分规则和超参搜索预算。验证集可选择权重，正式阶段冻结。单独按预测时刻报告事件标签的样本量、精度或召回率及校准误差，有时间掩码的样本仅进入其有效时刻统计。

**B3-R 的可执行设计。** 在同一场景内取一条安全、达到最低进度的候选 $a^{+}$ 和一条发生有责碰撞的候选 $a^{-}$，两者 4 秒进度相差初始上限 1.0 m，优先匹配导航指令与操作类别，可用性及配对条件在开发阶段登记。组内用相同训练候选池，每场景的候选对数设上限，保存正负 ID 和介入前后评分。增加 `softplus(m + s(a−) − s(a+))` 成对排序项，其中 $s$ 为世界模型评分，$m$ 为验证阶段确定并在正式测试前冻结的间隔。输出危险错选率、安全且前进的选中比例、进度、成对排序准确率和训练记录。该分支用 B1/B3-R 同候选池、同训练数据、同标注、同更新步数比较，B2/B3 不纳入正式主消融。若候选覆盖缺失主导，或标签质量不足以区分两类失效，带 E2 证据与导师定范围后再修改正式实验设计。

### E2 分支决策（2026-12-13）

1. 先汇总全体有效场景、存在可前进安全候选的场景，以及危险错选场景的数量和日志分布。对有明显碰撞对象的路口通行和切入病例独立查阅俯视回放。
2. 在共用候选池内检查候选前缀和首次分岔。开发版可用前 1 秒内轨迹中心差 ≤0.75 m、航向差 ≤10°，之后在 1–3 秒内明显偏离作为候选对筛选起点。同一候选对需由仿真轨迹事件标明分岔前后一致或不同的可观测风险，标签可疑则记为未知。
3. 启用 B2/B3 须同时有可恢复的选择错误、时序风险标签可稳定导出，以及明确发生在分岔后并伴随错误排名的可复现案例。建议开发报告用 **至少 10 个相关错选、来自至少 3 个独立日志**作为继续实现的项目门槛，展示有效近前缀候选对的分母和所有抽样失败。样本很少或多数事件时间无法核对时，优先验证 B3-R 的安全排序空间或提交范围调整。原模型的整体评分可用于识别排序错误，时序标签用于定位现象。风险发生时间是否构成可改善机制，由 B3 与 B2 的正式对照检验。该门槛是本项目的初始决策规则，可在察看正式结果前按开发样本量调整并登记。
4. 将主假设、诊断统计、采用分支、对照组和保留局限写入开题稿。冻结之后由正式测试检验既定假设。

## 5. 指标、配对与结果判定

### 固定候选、覆盖与选择诊断

- 固定每个 token 的候选数、候选索引、轨迹点坐标和时间栅格。NAVSIM 发布脚本配置 64 条候选，实际数量以完整导出为准。在缓存清单保存文件哈希及生成权重哈希。训练后至少随机抽查 20 个 token 的候选逐点值，正式对照按 ID 对齐。若某组无法复用候选，仅将其作为独立完整系统对照并单独注释。
- 有责碰撞危险候选定义为评测器原始 NC 小于 1 的候选。安全候选默认定义为 NC=1 且 DAC=1，报告逆行、闯灯等其他官方分项以限定此处的诊断含义。安全且有进展指安全候选在共同推演的 4 秒内沿参考路线正向前进至少 2.0 m。最低进度的初值用开发样本验证、在正式测试前冻结，给出单位、计算方法和失败标签处理规则。
- 在冻结的动态交互范围内构造常用诊断集合 **D**。它要求每个场景同时存在至少一个有责碰撞候选和至少一个安全、进度达线候选，且所有相关评测标签有效。路口通行可用导航路线经过路口、且未来 4 秒有对向或横向参与者轨迹经过冲突区作初筛。车辆切入可用邻道参与者在同一时域跨入自车路线车道作初筛。用开发数据锁定交互区域、位置与时刻阈值，在不显示组别和选择结果的条件下抽核场景标签。入选只由场景特征和共用候选结果决定，原模型和各组是否选错作为结果记录。报告全量数、D 的分母、各场景类别和唯一日志数。
- 对所有可评测场景，分开统计无安全候选、有安全候选但无进度达线候选、有安全可前进候选却选中有责碰撞、有安全可前进候选却选中安全低进度候选，以及选中安全可前进候选。可行驶区域失配等其余选择错误独立标注。
- 池内最优分差用同一诊断候选分数 $q$ 计算，等于逐场景 `max(q_i)−q_selected` 的平均值。若选用候选独立评分作为 $q$，提前写明计分、归一化和是否含相邻帧信息。全量 NAVSIM v2 EPDMS 通过官方聚合计算，包含跨时刻舒适性等项。原论文 v1 的 5.14 分仅作动机参考。

| 指标 | 计算与对照 | 拟争取的变化 |
|---|---|---|
| **困难场景危险错选率** | `D 中选中有责碰撞候选的场景数 / D 中有效配对场景数`。给出两组各自的分子、共同分母、新增错误与修复错误。 | 相对下降约 **20%**。绝对差报百分点，相对差为 `(原率−改进率)/原率`，原率为 0 时只报绝对差。 |
| **进度护栏** | D 上逐场景计算改进与原组在 4 秒参考路线前进距离的差，以米报告均值及配对区间，同时报全量官方 EP。 | 默认配对平均差的 95% 区间下界 **不低于 −0.5 m**。在开发阶段按进度分布校准一次并冻结。 |
| NAVSIM 全量 EPDMS | 先报告 `lam0` 同设置主对照。另报 NC、DAC、TTC、EP、EC 等分项和推理 P50/P95。 | 争取较实测同设置基线提高 **0.5–1.0 分**。 |

以上数值是工程目标。主结论先看危险错选率的配对改变量和进度护栏。改进组减对照组的错选率差的 95% 区间上界小于 0，且进度达到护栏时，支持所测条件下的选轨收益。区间跨 0 时报告估计值及不确定性。再用全量 EPDMS 及分项检查收益的适用范围。若风险收益伴随明显进度损失，报告两者的权衡。若完成闭环补充验证，按实际路线范围报告驾驶分、成功率和碰撞情况。 [NAVSIM v2.2 官方指标](https://github.com/autonomousvision/navsim/blob/v2.2/docs/metrics.md) · [Bench2Drive 成绩汇总](https://github.com/Thinklab-SJTU/Bench2Drive#benchmark)

### 配对统计、异常和重跑

1. NAVSIM 对同 token 配对，以原始驾驶日志为块，对危险错选差和进度差计算 95% bootstrap 区间。EPDMS 差值按正式聚合口径计算，若报告区间则保留帧间评测配对关系。帧数和独立日志数一起报告。若开展闭环补充验证，按路线 ID 配对，分场景报告，重复同一条路线的实验按路线或场景簇保留关联。验证阶段冻结随机种子，条件允许时至少 3 个训练种子，并报告各种子与汇总。实际只完成一个种子时，注明结论来自固定模型实例。
2. 记录 `MODEL_FAIL`（评测定义的碰撞、违规、任务超时或可归因于模型的输出失败）、`INFRA_FAIL`（网络、文件损坏、启动异常、服务端崩溃等有日志佐证的基础设施问题）和 `UNKNOWN`。模型失败进入官方分母和失败统计。基础设施问题按同一配置的预登记有限次数重跑，保留首次日志。未修复的缺失或无法归因项保留独立记录，配对分析报告有效分母、缺失名单和保守敏感性计算。可选闭环按实际路线清单与有效配对数报告结果。
3. 主表保留同一数据、同一候选数、同一推演设置和同一评分配置。若开展闭环补充验证，并行进程记录端口、GPU、路由名单和断点，结算前检查重复 route ID 及遗漏。报告 wall time、硬件、并行度和模型推理时延，以区分架构新增开销与批跑工程开销。

## 6. 输出、图表和可复现材料

每次实际运行至少包含 `manifest.json`、`config`、命令、原始日志、权重引用、逐样本明细、汇总和用于生成图表的脚本。敏感或许可受限的原始数据按官方要求管理，仓库记录数据获取方式及对应哈希。输出字段与[实验记录规范](实验记录规范.md)对齐：

| 输出 | 一行对应 | 最低字段 |
|---|---|---|
| `candidate_trace` | 场景中的一个候选 | `run_id, split, log_name, token, scene_type, candidate_id, pool_hash, traj, timestep_s, method, selected, model_score, nc_raw, dac_raw, progress_m_4s, first_collision_s, collision_actor_type, label_valid, runtime_ms` |
| `scene_summary` | 一个方法在一个场景的选择 | `token, log_name, method, n_candidates, n_safe, n_safe_progress, in_diagnostic_D, selected_id, failure_class, selected_nc, selected_progress_m, selected_score, pool_best_score, latency_ms, status` |
| `route_summary` | 一条可选闭环路线 | `route_id, route_xml_sha256, town, weather, scenario_type, seed, method, driving_score, success, route_completion, has_collision, elapsed_s, status, attempt_id, json_path` |

答辩时展示同场景同候选池的危险错选计数、进度变化、NAVSIM 全量成绩和消融结果。以下材料以实际运行文件生成：

1. **失败构成和主成绩图**。从全量样本分到候选覆盖、危险错选、保守错选和其它结果，列出分母。主柱图同时写上分子/分母、百分点差和置信区间，相邻图报告进度。
2. **同帧并排俯视图**。绘出候选池、原版选中轨迹、改进版选中轨迹、冲突对象和首个风险时刻。轨迹同轴、同尺度和同颜色规范，记录 token 或路线帧号。至少保留修复案例、改进后新增错误、仍失败案例。
3. **可选闭环案例**。若开展 E5，补充代表路线的配对结果，用同路线和初始配置并排展示轨迹、速度与碰撞或通行结果。
4. **阶段节点**。12-18 冻结开题材料，12-31 前按学校安排完成开题，1-31 完成开发消融，2-14 冻结正式协议，3-14 作为正式实验目标，3-28 冻结图表和权重。各节点的责任与回退条件由[时间安排](时间安排_v3_世界模型路线.md)统一维护。

主实验交付基线复现记录、可运行改动、冻结协议、NAVSIM 全量与困难场景评测结果、消融以及负结果分析。方法有效性按实际结果表述，每条结论应可追溯到代码、权重、数据与评测器版本。
